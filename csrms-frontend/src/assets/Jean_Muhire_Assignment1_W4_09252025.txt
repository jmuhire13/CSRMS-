FORMATIVE ASSIGNMENT


Compassionate Rwanda: Child Support and Resource Management System (CSRMS)
	

1. Mission Concept
Mission Statement:
My mission is to create a compassionate and supportive community in Rwanda by 2050 through organizations dedicated to the health and well-being of vulnerable populations, especially children. By establishing a Child Support and Resource Management System (CSRMS), the aim is to provide safe spaces where children can access healthcare, education, nutrition, and psychosocial support in a transparent and efficient manner.
Sector: Child welfare and community health.
Relevance:
Children in Rwanda and across Africa are highly vulnerable to poverty, malnutrition, limited schooling, and weak support systems. Existing programs lack efficient tracking and coordination tools, causing delays and wastage of resources. A technological solution that improves transparency, accountability, and timely support is both urgent and impactful.
2. Problem Statement
Despite many aid programs, children still face:
* Missed opportunities due to poor record-keeping.
* Resource wastage or delays because of misallocation.
* Lack of accountability and real-time updates in aid delivery.
Problem: Inefficient tracking and distribution of resources for child welfare due to the absence of an integrated, transparent digital system.




3. The Solution 
CSRMS is a web and mobile-based resource management platform for NGOs, schools, clinics, and caregivers. It provides a centralized tool to identify, track, and support vulnerable children.
Core features:
* Registration and profiling of children with needs data.
* Resource inventory (food, medical, education, psychosocial).
* Resource-to-need matching and delivery tracking.
* Real-time notifications and progress dashboards.
* Reporting tools for transparency and donor accountability.




4. Software Development Model: Agile
CSRMS will be developed using the Agile model because:
* It allows quick delivery of prototypes to test with NGOs and caregivers.
* Continuous feedback ensures cultural and contextual fit.
* Iteration works well for scaling; health first, then education, then psychosocial support.
Agile Steps for CSRMS:
* Gather user stories from NGOs, schools, social workers.
* Sprint planning: prioritize child registry + resource matching.
* Iterative builds: add dashboards, alerts, and reporting.
* Usability testing with stakeholders.
* Deployment with phased rollout and improvements.




5. Hypothesis of Solution


If NGOs, schools, and caregivers use an integrated platform for child resource management,
then:
* Resource wastage will reduce by at least 30%,
* Response times for child emergencies will improve significantly,
* Children’s access to education, nutrition, and healthcare will measurably increase.

1.         Introduction
1.1         Purpose
This document outlines the requirements for the Child Support and Resource Management System (CSRMS). CSRMS is a web and mobile platform designed for NGOs, schools, clinics, and caregivers to register vulnerable children, track their needs, manage available resources, and coordinate support delivery. This SRS describes the requirements for the complete system to ensure transparency, efficiency, and accountability in child welfare services.
1.2         Document Conventions
* Bold text is used for section headers and key terms.
* Italic text is used for emphasis.
* Functional requirements are labeled as FR (e.g., FR1, FR2), while non‑functional requirements are labeled as NFR (e.g., NFR1, NFR2). Sub‑requirements follow a hierarchical numbering format (e.g., FR1.1, FR1.2).
* Terminology, abbreviations, and acronyms used in this document are defined in the Glossary (Appendix A).
* 

1.3         Intended Audience and Reading Suggestions
This document is intended for the following audiences:
* Developers and designers: to use detailed functional and non‑functional requirements in building CSRMS.
* NGOs, schools, and clinics: as stakeholders who will use the system and provide contextual feedback during iterations. They may focus mainly on the introduction, overall description, and system features.
* Supervisors and academic reviewers: to evaluate the clarity, feasibility, and alignment of the system with the project mission. They should review the introduction, product scope, and requirement specifications.
Readers are advised to begin with the Introduction and Product Scope for project context, then proceed to Requirements sections most relevant to their role.
* 

1.4         Product Scope
The Child Support and Resource Management System (CSRMS) is designed to improve transparency, efficiency, and accountability in delivering child welfare services. It includes the following modules:
* Child Registration & Profiles: Create and store records of vulnerable children with detailed needs information.
* Resource Inventory: Track available resources such as food, medicine, educational materials, and psychosocial services.
* Needs‑Resource Matching: Automatically match resources to children’s needs to reduce waste and delays.
* Notifications & Reminders: Send real‑time alerts to stakeholders for urgent cases and upcoming deadlines.
* Reporting Dashboards: Generate analytic reports for NGOs, schools, and donors to ensure transparency and accountability.
* 

2.         Overall Description
2.1         Product Perspective
The Child Support and Resource Management System (CSRMS) is conceived as a standalone digital platform that directly supports NGOs, schools, and clinics in tracking child needs and managing resources. At present, many organizations rely on fragmented spreadsheets or manual reporting systems, which leads to inefficiencies and poor coordination. CSRMS fills this gap by providing a centralized platform with web and mobile access.
While initially designed as an independent system, CSRMS is built with flexibility for future integration with donor management platforms, government reporting systems, or third‑party data sources to enhance interoperability and scalability.


2.2         Product Functions
At a high level, CSRMS will provide the following core functions:
* Child Profiles & Resource Records (CRUD): Create, read, update, and delete records for children and resources, ensuring accurate and up-to-date data management.
* Role‑Based Access Control: Different access levels for NGOs, administrators, caregivers, and donors to maintain security and proper data handling.
* Real‑Time Notifications: Automated alerts for urgent cases (e.g., health emergencies, resource shortages) and reminders for deadlines.
* Data Dashboards & Analytics: Graphical dashboards and reports to provide transparency, monitor activities, and support evidence‑based decision‑making by NGOs and donors.
* 

2.3         User Classes and Characteristics
CSRMS will serve four primary user classes:
* Administrators (NGOs/Government Staff): Manage the overall system, approve major updates, and generate official reports. Typically use the system daily, with higher technical privileges.
* Social Workers/Field Officers: Register children and update information on health, education, and resource needs. Frequent users, with moderate digital literacy.
* Caregivers (Parents/Guardians): Primarily view their children’s support status and receive notifications. Occasional users, requiring a simple, mobile‑friendly interface.
* Donors/Funders: Access dashboards summarizing how resources were allocated and their impact. Infrequent users, focused on visual reports and transparency.
* 

2.4         Operating Environment
* Client Platforms:
   * Mobile: Android for initial release; iOS for planned in future updates.
   * Web: Built with React to support NGO administrators and donors via browsers.
* Backend Environment: Node.js with Express.js for REST API services and server logic.
* Database: PostgreSQL, selected for its strong relational queries and reliability in generating transparent reports for NGOs and donors.
* Frontend: React (web) and React Native (mobile) to create responsive, cross‑platform interfaces.
* 

2.5         Design and Implementation Constraints
* Must work offline with later sync
* Comply with Rwanda’s Data Protection Law
* Limited budget: open-source tools preferred


2.6         User Documentation
* Quick start guide
* In-app tutorials for first-time users
* FAQ and support chatbot


2.7         Assumptions and Dependencies
* Users have access to smartphones or PCs.
* Internet connectivity is intermittent in rural areas.
* Collaboration of NGOs and schools is ensured.


3.         External Interface Requirements
3.1         User Interfaces
* Dashboard for admins
* Mobile forms for social workers
* Alerts via SMS/app notifications
* Clean, child-friendly visuals for clarity


3.2         Hardware Interfaces
* Smartphones/PCs with 150MB space minimum


3.3         Software Interfaces
CSRMS will interact with the following software components:
* Database Integration: PostgreSQL as the main database storing all child records, resource inventories, and activity logs.
* External APIs: Secure REST APIs will be developed to integrate with NGO donor management platforms and government reporting systems. These APIs will allow exchange of data such as donations received, resource allocations, and beneficiary impact reports.
* Authentication Services: Firebase Authentication (or equivalent) will be used for secure login and user management.
* Communication Protocols: All data exchanges will occur over HTTPS with JSON message formats to ensure security and compatibility.
* 

3.4         Communications Interfaces
* HTTPS for secure data transfer
* SMS/notification gateway
